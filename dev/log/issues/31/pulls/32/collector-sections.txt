2:// Collects packages published by konard and the organizations konard founded or
3:// worked in, across as many public package registries as can be queried
4:// without credentials, and writes docs/case-studies/issue-7/data/registries.json.
5://
6:// Two complementary discovery strategies are used:
7://   1. Account based: list everything owned by a registry account / scope /
8://      namespace (npm user + org listings, crates.io user, NuGet owner, PyPI
9://      user, Docker Hub namespace, GitHub Packages pages, ...).
10://   2. Manifest based: walk the git tree of every repository listed in
11://      repositories.json, read publishable manifests (package.json, Cargo.toml,
12://      pyproject.toml, go.mod, *.gemspec, composer.json, pubspec.yaml, ...)
13://      and look the declared names up in the matching registry. A hit only
14://      counts when the registry metadata points back to one of the owners, so
15://      name collisions with unrelated packages are discarded.
16://
17:// Usage: node experiments/collect-registries.cjs [output-dir]
18:// Requires Node 22+ (global fetch) and an authenticated `gh` CLI for git trees.
